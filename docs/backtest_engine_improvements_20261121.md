# GeneralBacktest 回测引擎待优化需求与验收用例

日期：2026-11-21

状态：待实现的功能设计，不代表下列能力已经具备。

检查范围：本仓库 `src/GeneralBacktest/`，重点为现金回测 `run_backtest_with_cash()`，兼顾普通权重回测与双轨回测。

## 1. 目标与边界

将 GeneralBacktest 完善为可配置、可审计的“目标持仓或订单 → 实际成交 → 持仓及现金 → 估值与绩效”引擎。目标是灵活性、准确性、严格性、通用性，而非增加某一种策略的专用逻辑。

**本文不涉及**因子计算、信号生成、选股排序、预测期限、模型训练、组合优化目标或如何确定目标权重。引擎接收调用方提供的目标或订单，以及带日期和可得时点的交易资格、交易许可、价格和事件数据；只负责验证和执行。

股票池在本文中仅表示**允许持有、允许新增买入、要求退出的外部资格状态**，不是引擎内部选股。风格或行业优化也不属于本次范围；可提供实际持仓、成交后回调及外部检查接口，但不硬编码某个指数或策略的风险限制。

必须保留两类独立配置：

- **无成交量／成交额限制的现金回测**：仍执行现金、价格、手续费、交易许可、最小交易单位及所选结算规则；不要求提供任何市场量额数据。
- **有容量约束的现金回测**：按用户明确启用的成交股数、成交额或参与率限制成交；不把容量限制和现金账户绑定。

无限容量不意味着允许停牌成交、忽略现金不足或使用未来价格。

## 2. 已有能力与本次发现

### 2.1 可以保留和复用的能力

- 任意调仓日期和目标权重输入。
- 现金、实际股数、买卖分别计费、滑点、最小交易单位。
- `position_ratio_col` 总仓位控制。
- `volume_data=None` 时不施加成交量约束。
- 买卖共用或独立的可成交股数上限；启用后缺失记录按零额度处理。
- 净额／毛额交易模式、双轨账户模式及复权相关接口。
- 交易、持仓、现金和净值输出。

现有能力仍应通过统一的账务与事件契约约束，不应仅凭接口名称判断是否符合所需回测语义。

### 2.2 已确认的不足

| 编号 | 当前行为或不足 | 影响与证据 |
| --- | --- | --- |
| G01 | 无原生的停牌、涨跌停和分方向许可字段处理 | 小样本传入 `suspended=True`、`can_buy=False`、`limit_up=True` 后仍买入 50 股；显式买入股数上限为零才会阻止交易。额外列不会自动成为交易约束。 |
| G02 | 缺失当日估值时，现金分支跳过对应持仓市值 | 500 元现金＋500 元股票，股票中间一天缺价、之后恢复原价，净值输出 `1000 → 500 → 1000`。持仓没有消失，但被漏估值。 |
| G03 | 缺少独立的待执行订单和事件驱动重试 | 第二天卖出因零额度受阻，第三天无新目标时不重试，原股票继续保留。当前主要在有目标权重的日期执行交易。 |
| G04 | 无完整退市与资格生命周期状态机 | 未发现统一的退市生效、强制退出、终止交易、结算、应收款及未知事件时点处理。 |
| G05 | 目标输入自动归一化，现金语义需要额外配置 | 不传 `position_ratio_col` 时，权重和小于 1 不能直接表示保留现金；空目标、零目标、无新目标需要显式区分。 |
| G06 | 定仓时间与成交时间未完全分离 | 单轨默认 `sizing_price='buy_price'`；`prev_close` 缺价时仍可回退至当日成交价／收盘价。双轨分支尚未实现同等的事前定仓控制。 |
| G07 | 内置 `benchmark_weights` 使用简化计算 | 现金分支的基准不走相同的现金、费用和成交限制流程，并在调仓日先更新目标再计算上一日至当日收益，存在区间归属差异。不能作为严格同口径对照。 |
| G08 | 绩效以第一条已记录净值为起点 | `pct_change().fillna(0)` 和首末净值比可能排除首次建仓前至首次建仓后的费用影响。账户扣费不等于绩效完整计费。 |
| G09 | 交易权限、未知数据和容量为零缺少统一原因体系 | 无法清楚区分“明确不能成交”和“数据不足，无法判断能否成交”；统计上的零成交不足以表达原因。 |
| G10 | 缺少跨模式的一致性与异常事件测试 | 本次仓库现有 7 项测试通过，主要覆盖总仓位和复权调整；不能据此证明停牌、退市、跨日重试及基准对齐正确。 |

## 3. 统一账户与事件契约

### R01：账户是唯一事实来源

账户应维护：实际持仓股数、可卖数量、已结算现金、可交易资金、冻结资金、应收应付、最后有效估值及其时间。字段可以按账户模式裁剪，但不能把目标权重当作实际持仓。

每个事件之后满足账务恒等式：

```text
资产净值 = 现金 + 持仓估值 + 应收款 - 应付款
买入现金减少 = 成交数量 × 成交价格 + 买入费用
卖出现金增加 = 成交数量 × 成交价格 - 卖出费用
```

无融资模式下不得产生超过数值容差的负可用现金。未成交部分不应改变持仓、重复扣费或凭空释放冻结资金。外部出入金、账户内部划转、交易、分红和退市结算必须分类记录。

### R02：分离目标、定仓、执行和估值时间

至少区分 `decision_time`、`order_time`、`execution_time`、`valuation_time` 与数据 `available_at`。日频输入也应通过配置声明相应事件顺序。

- 下单数量只能依赖下单时可得的数据；实际成交使用成交时价格。
- 严格模式下，事前定仓价缺失不得静默回退至未来成交价或收盘价；应报错或按明确配置跳过订单并记录。
- 可保留“按执行价格精确再平衡”的研究模式，但必须显式标记该假设，不能标为盘前可执行订单。
- 首个回测日需要事前价格时，可输入预热价格；预热数据不产生回测期内交易或收益。
- 净额、毛额、先买后卖、先卖后买及双轨模式共用时间校验。未来卖出所得不得资助更早的买单。
- 旧持仓赚取前次估值至本次成交的收益，新持仓只从实际成交时开始计收益；不得用新权重追溯分配过去收益。

### R03：明确目标持仓输入语义

提供明确的输入模式，而非隐式推断：

| 输入模式／状态 | 规定行为 |
| --- | --- |
| 绝对权重 | 不自动归一化；长仓无杠杆模式下，权重和小于 1 表示现金，大于 1 报错。 |
| 相对权重＋总仓位 | 先按声明归一化，再乘总仓位；保持现有功能，但写入运行配置。 |
| 目标股数／金额／显式订单 | 可分阶段支持；单位和定仓价格必须清晰，不再解释为权重。 |
| 无新目标 | 保持目标状态，照常处理估值、订单与生命周期事件；是否持续追踪旧目标由配置决定。 |
| 显式空仓目标 | 尝试清仓；受阻持仓仍保留并按订单有效期处理。 |
| 完整目标快照中缺少某资产 | 其目标为零；不得删除实际持仓。 |
| 增量指令中缺少某资产 | 不修改该资产的目标；不得与完整快照混用。 |

允许调用方在实际成交后获取状态并产生下一批目标；引擎不负责生成该目标。

## 4. 可配置交易限制

### R04：交易许可与容量分别建模

交易许可至少支持分方向 `allowed / blocked / unknown`，并携带原因、事件有效期和来源。容量为可选、独立模块。

| 配置 | 应有语义 |
| --- | --- |
| 未配置容量模块 | 不施加成交股数／成交额／参与率限制；无需量额输入。 |
| 明确容量为 0 | 该方向不成交；不是无限容量。 |
| 启用容量但记录缺失 | 严格模式阻断相关订单或运行；允许显式选择“视为零容量”，但必须标记缺失原因。不得视为无限容量。 |
| 未配置许可模块 | 通用研究模式可假设有效价格下可交易，并在报告声明；股票严格模式须提供许可数据。 |
| 许可为 unknown | 股票严格模式不能当作 allowed；保留可信检查点与错误明细。 |
| 共享容量 | 同一资产、执行时段内买卖及多条订单共同扣减；多账户是否共享由配置明确。 |
| 独立容量 | 买卖分别计数；不能误扣另一方向额度。 |

必须支持 `capacity=None` 与现金账户同时使用。原有 `volume_data=None` 行为应作为兼容性验收项。

可选容量类型：股数上限、成交额上限、成交量／额参与率。多个限制同时启用时，按各自单位计算后取最严格的可执行数量。成交额预算是否包含费用应明确定义，建议市场成交额不含费用，现金预算包含费用。

日总成交量、全天封板比例、全天 VWAP 等事后数据用于日频撮合代理时，应记录为执行假设；不能用于声称已在盘前确定精确订单。

### R05：涨跌停规则由市场适配层提供

核心引擎不硬编码固定涨跌幅、板块或交易所制度。适配层可以提供官方价格边界、无涨跌幅限制状态和分方向许可；规则按市场、证券、日期和执行时段配置。

支持两类不同研究约定：

- 单向限制：例如某状态下只禁止买入，或只禁止卖出。
- 双向限制：例如使用指定时点触板或全天封板比例规则，两个方向均禁止。

引擎只执行已声明规则，不自行把“涨停”等同于必然双向不可交易。价格精度、最小变动单位和阈值等号归属必须确定。若阈值配置为“严格大于 80%”，80% 与超过 80% 的结果必须不同。

### R06：停牌与估值独立

明确停牌时禁止相关交易，但已有持仓仍属于账户。支持经配置沿用最近有效估值，记录估值来源、原始价格时间、连续陈旧天数；复牌后从最后有效估值计入累计变动一次。

必须区分：

1. 明确停牌导致没有成交价格；
2. 有有效估值、但不能成交；
3. 原因未知的价格缺失；
4. 正式减值或终止结算导致的零价值。

第三类在严格模式下报错，不能伪装为停牌；第四类必须由显式事件授权。不得因缺价漏计市值，也不得把填充的估值价格当作可成交价格。

### R07：股票池资格与生命周期

外部资格输入应至少区分 `allow_new_buy`、`allow_hold`、`exit_required`。新股年限、ST、退市整理期、指数或自定义池成员等具体规则由外部生成，引擎不负责计算排名或挑选替代证券。

- 仅禁止新增买入时，可以继续持有，是否允许减仓按卖出许可处理。
- 要求退出时生成退出意图；**强制退出不能覆盖停牌、跌停等卖出限制**。
- 普通股票池变更不能直接删除持仓或把持仓价值改成现金。
- 资格恢复后可重新接收合法订单；不能因为历史 ST 状态永久封禁。
- 即使当日没有新目标，也要处理资格变化、已有退出意图和账户事件。
- 数据只需覆盖实际持仓、活跃订单及相关目标，不应因完全无关证券的缺失阻断运行。

### R08：退市、终止交易与结算

分别处理停止新增交易、要求退出、正式终止交易、持仓注销和实际结算。终止交易不是成交，不能伪造卖单或计入交易换手。

配置支持：已知结算价与回款日期、应收款等待结算、显式核销为零、声明为研究假设的最后有效估值结算。结算规则缺失时严格模式阻断，不默认零损失回款，也不默认永久按旧价持有。

结算采用幂等事件 ID，防止重复回款。正式终止交易后禁止普通买卖；结算日之前的应收款不能自动当作可买入现金。

## 5. 订单、结算与费用

### R09：订单状态与跨日执行

维护订单 ID、方向、提交数量、累计成交数量、剩余数量、状态与原因。至少支持当日有效、持续有效、到期失效和撤单；部分成交不得丢失剩余数量。

- 当日有效订单未成交部分到期取消，不隐式重试。
- 持续有效订单在后续执行事件重试，不依赖是否有新的目标输入。
- 新目标如何替换旧订单必须显式配置；避免旧卖单与新买单冲突。
- 受阻退出恢复后执行；毛额模式若清仓失败，不得假装已空仓后无限重复买回。
- 净额模式下，目标和实际数量相同不产生虚拟往返交易。
- 所有拒绝、零成交、部分成交和撤销都输出明细；原因可同时包含现金、容量、许可等，不仅保留最后命中的原因。

### R10：交易单位与结算规则通用化

允许按资产配置买入单位、卖出单位、零股清仓规则和数量精度。支持整数股、整手及允许碎股的研究模式，不强制所有市场使用 100 股一手。

结算策略至少明确持仓何时可卖、卖出资金何时可用于交易／提现。可配置 T+0、T+1 或相应事件规则，不把双轨轮换视为通用结算规则的替代品。

双轨或多账户内部划转不产生外部资金流、投资收益或市场成交额；账户分别满足约束，总账与分账一致。

### R11：费用、滑点和公司行动

保留买卖分别按成交金额计费，并允许配置最低费用、固定费用、单边税费及分段费率。费用基于实际成交，零成交不收费；费用计算应参与现金可负担数量判断。不能买入后仅把负现金截成零。

滑点改变成交价，手续费单独记账，不能重复扣减。若已有容量约束，成交金额必须使用与容量定义一致的成交价口径。

公司行动区分现金分红、拆并股、送股、应收分红与到账。显式股数／现金事件模式和复权总回报研究模式互斥，防止复权价格、股数调整与分红重复计算。累计复权因子与单次调整比例必须使用不同字段契约，不能直接混用。

## 6. 绩效、可审计性及一致性

### R12：净值基点、区间归属与换手

保留首次交易之前的初始资本基点，使首日费用计入总收益、回撤和收益序列。只有一天的回测也应输出正确的首日盈亏，不能因为无 `pct_change` 返回零收益。

显式区分初始资本基点、交易日观察数与年化区间数。存在外部资金流时，采用声明的时间加权或资金加权口径，不能直接用现金注入后的净值涨幅当投资收益。

至少同时输出：实际买入金额、实际卖出金额、费用、分方向换手、双边换手、半双边换手。半双边换手可定义为 `(买入金额 + 卖出金额) / (2 × 交易前净值)`，报告必须写明分母估值时点及是否包含首次建仓。非调仓日也有零换手记录，避免“仅调仓日平均”冒充“每日平均”。

引擎可接受通用的日交易预算，但不负责优化器如何满足预算。成交后的实际仓位必须能由外部重新检查；若现金、容量或手数改变实际权重，不得继续报告目标权重的约束结果。

### R13：基准与策略共用执行路径

需要同口径比较时，策略和基准各自从相同初始资金开始，使用同一账户、许可、费用、估值及事件规则，只改变外部输入的目标或订单。

简化指数或理论基准仍可保留，但必须标明“参考收益曲线”，不能与现金账户基准混淆；不得默认将无费简化基准称为同口径基准。允许二者有不同配置时，报告逐项列出差异。

### R14：严格验证、复现与性能

- 检查重复键、非法价格、非有限数值、负容量、不合法数量、日期顺序和资产身份冲突；零价格只能用于声明允许的估值／结算事件，不能普通成交。
- 配置中不受某模式支持的参数应报错，不得静默忽略。
- 输出配置、代码版本、输入版本／摘要、事件与时间假设、完整性状态、可信截止时间。
- 异常时保留失败原因和最后可信检查点；部分结果不能标记为完整回测。
- 支持检查点续跑，连续运行与续跑在相同输入下账本一致；事件不能重复应用。
- 行顺序和分块方式不应无意改变结果；现金不足时订单优先级必须确定、可配置、可审计。
- 价格、许可和事件可预处理为数组或索引，但不能以批处理性能为由丢失时序约束。按日遍历全部历史交易记录的统计应改为增量累计。

## 7. 验收用例

除另有说明，金额以元计；测试使用合成价格，禁用无关费用与滑点，明确交易日、执行时点、估值时点和事件可得时间。每个用例同时核对现金、持仓、成交／事件明细与净值，不仅检查最终收益。

| T04 股数及成交额共同限制 | R04 | 价格 10，订单 100 股；股数上限 80、成交额上限 500 | 成交 50 股，两个预算明细正确。 |
| T05 共享与独立容量 | R04 | 同资产卖 60 股再买 60 股，总容量 100；另跑买卖各 100 | 共享时买最多 40；独立时买卖均可 60；使用允许该序列的结算模式。 |

### 7.1 属性与交叉测试

- 每笔交易后现金和持仓变动等于成交账本；每天净值等于总账资产负债之和。
- 已知价格恒定、无费用和资金流时，任意合法交易序列不应创造净收益。
- 不可交易资产的成交数量始终为零；缺失估值不得无声明消灭资产。
- 执行数量不超过订单余量、可卖数量、启用的容量及含费现金预算。
- 同一输入重复运行、打乱无语义行顺序、改变数据分块，应得到一致结果；现金优先级以显式规则决定。
- 使用小型独立参考账本交叉验证，不依赖被测撮合函数自身计算预期值。
- 对现金单轨、双轨和支持的执行顺序运行共同适用的测试；不适用项必须显式拒绝，不能表面通过。
- 已有 7 项测试继续作为回归测试，但不能替代上述事件、时间和账务测试。

### 7.2 规模与性能验收

使用合成数据按交易日数、资产数、持仓数、订单数和事件密度分层测试，例如 250／2500 日、100／5000 资产，以及高缺价、高受阻、频繁部分成交场景。记录初始化、逐日执行、明细输出耗时及峰值内存。

性能阈值应根据目标机器与使用规模另行确定，不在未测量前承诺。性能优化前后必须通过相同账本一致性测试；不得只保留汇总净值而丢弃强制审计明细，允许明细分批落盘。

阶段只是实施顺序，不意味着通过 P0 就具备完整股票回测能力。准备用于含停牌、退市等事件的正式股票回测时，相关 P1 和 P2 功能同样必须通过验收。

最终交付应包含：

1. 各模式的输入契约、默认值、支持／拒绝参数清单及迁移说明。
2. 无容量限制现金回测、有容量限制现金回测、股票事件回放三个最小可运行示例。
3. 完整订单／成交／持仓／现金／估值／事件账本和运行完整性报告。
4. 本文用例的自动测试、独立参考账本及明确的数值容差；数量和事件次数应精确，浮点金额容差应按币种与账户规模定义。
5. 同输入基准与策略一致性证据、跨模式测试结果和连续／续跑一致性结果。
6. 对尚未实现的能力明确报错或标记不支持，不把外部适配需求包装为内置能力。
